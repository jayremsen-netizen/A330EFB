# 配载与重心工程模型

本模块把航班计划中的旅客、行李、货物和燃油转换为可核对的分舱配载，按纵向力矩计算零燃油、停机坪、起飞和着陆重心。页面上的质量—重心图直接使用当前计算结果。模型用于 A330EFB 投标演示，参数未以特定飞机称重记录或获批装载手册校准；结果不能作为实际运行载重表或配平设置。

## 输入与质量闭合

`LoadingInput` 保存四个客舱的旅客人数，以及三个货舱各自的行李重量和额外货物重量。旅客重量只包含 `paxKg`；每位旅客的 `bagKg` 计入货舱，避免把行李重复加入客舱质量。四个客舱人数必须等于计划 `pax`，货舱行李合计必须等于 `pax × bagKg`，货舱货物合计必须等于 `freightKg`。

每个货舱同时受到行李与货物合计容量约束。非有限数、负数、小数人数、站位数不符、分配合计不符或站位超限都会撤销计算点，返回 `status: invalid` 和具体原因。浮点质量合计使用 0.000001 kg 的数值比较容差，不代表允许超额配载。输入变化后直接重算，没有可继续采用的历史结果。

“按计划自动分配”是显式操作：按各站位容量比例分配总量，将整数人数余量按站位顺序补齐。重量分配保留两位小数，最后一舱承接数值余量。改变航班旅客或货物总量不会自动覆盖已有分舱方案；原方案会出现合计不符，用户可以调整站位，或再次选择自动分配。自动分配只提供演示初值，不声称优化重心或地面装载顺序。

## 站位与几何

工程坐标以假定机鼻原点为 0 m，向后为正。客舱 A/B/C/D 的力臂分别为 18/26/34/42 m，容量为 100/120/120/96 人。前、后、散货舱力臂分别为 22/36/42 m，容量分别为 20000/20000/4836 kg。页面站位图绘制这七个集中载荷点，不表示真实座椅排位、实际舱门或货物装载位置。

零燃油基本质量取现有机型包的 OEW 127000 kg。OEW 力臂为假定值 31.1 m，LEMAC 为假定值 29 m，MAC 为假定值 7 m；它们共同定义本工程模型的 % MAC 坐标。全部燃油采用固定力臂 31.8 m。这个简化使燃油消耗能够通过质量和力矩同时改变重心，但不模拟 A330 分油箱用油、配平油箱转输及横向不平衡。

上述几何、分区容量与力臂均由本项目设定，没有将 Headwind 的图表范围或绘图坐标解释成飞机几何。机型配置变更应增加模型版本；不能仅修改页面标签而保留原数值。

## 计算方法

每个载荷站位的质量矩为 `Mi = mi × xi`，单位为 kg·m。零燃油质量与力矩为：

```
ZFW = OEW + Σ(客舱人数 × 单人重量) + Σ行李 + Σ货物
Mzfw = OEW × xOEW + Σ(客舱质量 × 客舱力臂) + Σ(货舱质量 × 货舱力臂)
```

对某阶段剩余燃油 `F`，总质量 `W = ZFW + F`，总力矩 `M = Mzfw + F × xFuel`。重心力臂 `xCG = M / W`，重心百分比 `%MAC = (xCG − LEMAC) / MAC × 100`。停机坪燃油来自 `rampKg`；起飞燃油为 `rampKg − taxiKg`；着陆燃油由航路及备降燃油模块传入。传入 0 kg 会计算零燃油着陆点；不传入着陆油量则返回 `landing: null`，明确提示尚未校核。

公式依据 [FAA《Pilot’s Handbook of Aeronautical Knowledge》第 10 章](https://www.faa.gov/sites/faa.gov/files/12_phak_ch10.pdf) 的质量、力臂与力矩方法。该资料同时说明燃油消耗和载荷移动可改变重心；它不提供本项目的 A330 参数。

## 模型约束与图形

重心包线以三个质量节点插值：127000 kg 对应 20–40% MAC，180000 kg 对应 15–40% MAC，251500 kg 对应 20–37% MAC。节点间采用线性插值。包线是人为设置的演示约束，不是 A330 认证包线。

各阶段另行校核质量：ZFW 181000 kg，停机坪 251500 kg，起飞 251000 kg，着陆 191000 kg。既有项目的 OEW、MZFW、MTOW 及货舱合计质量，与 [Headwind 固定提交的 airframe.json5](https://github.com/headwindsim/aircraft/blob/41eace79ed442696a6361dc72947954c9a6cf5cb/hdw-a339x/src/base/headwindsim-aircraft-a330-900/config/a339x/a330-941/airframe.json5) 保持一致；这只表示软件配置一致，不表示获批数据校验。停机坪和着陆上限在本模块作为演示约束使用。

数值有效但重心或质量超限时保留诊断点，返回 `engineering-infeasible` 和 `canAdopt: false`。只有已计算阶段全部满足质量与重心约束才返回 `engineering-feasible`。上层工作流还要验证目的地和备降两种着陆情景，并确认相应燃油与配载签名；模块自身可在缺少着陆油量时校核地面与起飞阶段，但不代表完整工作流已验收。

包线图横轴为 % MAC，纵轴为质量。四个计算点分别对应 ZFW、RAMP、TOW、LW；两个虚线标识为零燃油与着陆质量上限。超过图形默认范围的诊断点会扩展坐标范围，不会通过裁剪隐藏超限。站位图与包线图均由模型数据绘制。

## 地面装载与下客

`calculateGroundCG` 以已确认计划分配为比例基准。当前旅客人数与计划人数之比用于缩放各客舱载荷，当前行李及货物合计与计划货舱总量之比用于缩放货舱载荷。加上当前燃油质量矩后，返回当前总质量、力矩及重心。这个过程是比例装载工程假设，没有逐舱先后装载含义。

满载且燃油等于计划停机坪燃油时，地面计算与 RAMP 点一致；空载时只保留 OEW 与实际燃油。当前人数或货物超过计划、数值无效，或计划配载不合法时返回 `null`。调用方必须另外验证当前计划的配载确认签名，避免把未确认的分配显示成已采用方案。

## 接口与追溯

核心接口位于 `local-extensions/loading/index.ts`：

```
defaultLoading(flightProjection) → LoadingInput
calculateLoading(flightProjection, input, landingFuelKg?) → LoadingResult
loadingSignature(flightProjection, input, landingFuelKg?) → string
calculateGroundCG(flightProjection, input, {pax, cargoKg, fuelKg}) → LoadingPoint | null
```

签名包含模型完整参数及来源、输入数值投影、分舱分配和着陆燃油。签名不包含界面是否已确认等状态，防止接受状态反过来改变数值签名。`LoadingResult` 携带独立输入快照、模型参数、来源链接、计算时间、站位力矩、阶段结果和诊断。JSON 导出直接序列化当前结果。页面通过 `flight`、`input`、`onChange` 和可选 `onAdopt` 等属性接入，数据持久化和跨模块确认由上层负责。

## 验证范围

`tests/loading-engine-tests.cjs` 通过公开接口检查质量与力矩独立解析、旅客前后移动、合计不匹配、站位与数值边界、前后重心超限、零载荷和满座、四阶段质量边界、燃油消耗、签名及输入快照、地面满载/半载/空载守恒。测试结果写入 `.artifacts/loading/engine-tests.json`。这些验证检查工程模型实现的一致性，不验证飞机专用参数真实性。
