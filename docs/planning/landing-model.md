# 工程着陆模型设计

本模块补充 A330EFB 投标演示中的到达着陆评估流程。输入来自当前航班的目的地或备降场、独立的跑道和气象条件，以及燃油规划输出的预计着陆重量。输出包含工程进近速度、分段距离、LDA 余量、场长工程限重及可导出的计算快照。

模型编号为 `A339-LANDING-ENGINEERING-DEMO`，初版参数版本为 `0.1.0`。这是一套原创质点工程模型，没有移植 Airbus 性能表。机翼面积、升力系数、速度倍率、摩擦系数、反推力及适用包线全部列为工程假设，尚未用 A330 试飞或经批准性能资料校准。界面、报告和 JSON 均保留这一属性。

## 输入与模块边界

`landing/types.ts` 定义独立的 `LandingInput`。`target` 选择目的地或备降场；`airport` 必须与当前航班对应机场一致；`weather.station` 必须与 `airport` 一致。跑道编号、航向、LDA、标高、坡度和表面状态均来自该对象。模块不读取起飞跑道、起飞机场 METAR 或旧着陆页面的 Redux 状态。

`EngineeringLanding` 接收工作流提供的 `flight`、`input`、`onChange`、`mass` 和 `workflowSignature`。组件只持有当前计算快照，不另建存储。重量对象包含 `landingKg`、来源说明、签名、有效状态和阻断原因。父工作流负责配载、燃油规划、航班确认、窗口冲突和预计重量的连贯性；着陆页面不会自行把无效重量替换成固定值。

切换目的地 / 备降场时保留原有条件，让机场不匹配成为可见错误。只有用户点击“重设为目的地工程示例”或“重设为备降场工程示例”，才创建该机场的新输入。示例中的跑道和天气明确标注为手工演示样例，不声称来自机场权威资料或观测报文。用户也可逐项修改独立条件。

主计算接口如下：

```ts
calculateLanding(input: LandingInput, massKg: number,
  context: LandingContext): LandingResult
```

`LandingContext` 包含航班标识及日期、重量来源、重量签名和整个工作流的签名。输出再附加模型版本及完整参数签名，使机场、质量来源或模型变更能够失效旧结果。

## 大气、风和工程速度

压力由机场标高及 QNH 通过对流层静力关系求得，温度直接使用输入 OAT；密度使用干空气状态方程。由机场压力反解压力高度，支持范围为 −1000–8000 ft。边界比较只使用 `1e-6 ft` 的浮点容差，越界 `0.001 ft` 已在回归测试中验证为拒绝。

失速真空速由升力平衡确定：

\[
V_{s,TAS}=\sqrt{\frac{2mg}{\rho S C_{L,max}}},\qquad
V_{ref,TAS}=1.23V_{s,TAS}
\]

随后使用亚声速可压缩关系换算 CAS。FULL 和 CONF3 使用两组公开列示的假设升力系数。CAS 用于显示，TAS 用于升力和阻力计算，地速用于距离积分；三者不混用。NASA 的公开升力方程仅支持上述通用关系，没有为本项目提供飞机专用系数。[NASA Glenn：Lift equation](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/lift-equation-2/)

进近附加速度取手工输入、5 kt、稳定迎风的三分之一和阵风增量四者的最大值。超过 20 kt 的阵风增量不接受外推。这个算法是演示规则，不是 Airbus 的 VLS 或 GS mini。稳定风投影到跑道方向后全额用于地速；阵风参与速度附加量和风分量包线检查。风向和跑道航向必须使用同一真 / 磁基准，本模块不做磁差换算。

## 空中段与地面减速

模型从着陆阈值上方 50 ft 开始，以 3° 路径下降到假设的 5 m 拉平高度，再以 4 秒拉平过渡到接地。拉平期间 TAS 线性下降到进近 TAS 的 96%，距离使用这一段的平均地速。接地后，模型只加入一次 2 秒制动延迟。

地面减速按地速每步不超过 `0.25 m/s` 做中点积分。对于一个速度步长：

\[
\Delta t=\frac{m\Delta v}{F_{stop}},\qquad
\Delta s=v_{mid}\Delta t
\]

总停止力由空气阻力、轮刹车、反推和坡度分力组成。轮刹车的上限为 `μ·max(0, mg−L)`。干、湿路面分别使用假设摩擦系数 `0.34`、`0.18`。反推按每台 `26000 N` 假设，并在地速低于 `35 m/s` 后线性衰减至零。

LOW、MED、MAX 分别对应 `1.7`、`2.5`、`4.0 m/s²` 的总减速度假设。模型先用阻力、反推和坡度抵扣目标减速度，再请求剩余轮刹车力，并受摩擦上限限制。因此，在路面摩擦充足、MED 已达到目标时，增加反推不会虚构更短的停车距离；在湿路面摩擦受限时，反推可改善减速度。该特性有独立回归验证。MAX 仅为模型档位，不表示 A330 飞行程序中某个按钮的使用许可。

SVG 纵剖面使用本次轨迹的距离、高度和坡度绘制，距离分解条与模型分段结果共用数据。横纵坐标采用不同尺度，界面明确标识；图不作为飞行操纵指引。

## 距离比较与场长工程限重

未乘系数距离为三段之和：

\[
D_0=D_{air}+D_{delay}+D_{brake},\qquad
D_{required}=kD_0,\qquad
Margin=LDA-D_{required}
\]

距离系数默认 `1.15`，录入范围为 `1.15–1.67`，只应用一次。FAA 到达评估资料和 Airbus 的制动试验说明用于解释“当前到达条件、着陆距离及附加余量”的概念；这些参考资料不验证本项目的距离值，也没有使其成为签派 RLD 或法规符合性计算。[FAA SAFO 19001](https://www.faa.gov/sites/faa.gov/files/other_visit/aviation_industry/airline_operators/airline_safety/SAFO19001.pdf)、[Airbus Brake Testing](https://safetyfirst.airbus.com/airbus-brake-testing/)

场长限重在 `120000–191000 kg` 内按 `100 kg` 档位完整搜索。它返回满足当前 LDA 的最高档位，不依赖自动刹车控制规律的单调性假设。所有档位都不可行时返回空值；达到质量包线上限时明确显示“非结构审定限值”。这个搜索只解决当前模型下的距离约束，不保证该质量对应当前航班可实现的配载或油量。

LDA 直接作为从着陆阈值开始的可用距离。本模块不再次扣减移位阈值，也不把 TORA、TODA、ASDA 替代 LDA。

## 状态、失效与导出

计算状态分为四类：

- `invalid`：缺项、非有限数、机场或天气站错配、无重量来源等输入问题。
- `unsupported`：污染跑道或超出已声明的工程包线。
- `engineering-infeasible`：物理计算完成，但乘系数后的距离超过 LDA；保留红色诊断距离及诊断速度，不显示可行结论。
- `engineering-feasible`：当前输入满足模型中的 LDA 约束，含义限定在该工程模型内。

前两类状态没有 `solution`，不会保留上次速度和图表。页面每次渲染都比较当前输入、重量、上下文和模型签名；签名不同、重量无效或父工作流阻断时，旧结果立即不可显示和导出，不依赖延迟清理副作用。

JSON 导出包含参数、来源、模型签名、输入、重量来源、航班上下文、分段数值和轨迹。HTML 导出使用相同快照和 SVG，可打印或另存 PDF。输入文本经过 HTML 转义，导出页面不加载外部图片或脚本。窗口测试接口 `__LANDING_ENGINEERING__` 只返回当前有效快照，并在组件卸载时清理。

## 支持范围与验证

当前模型支持质量 120–191 t、温度 −20–45 °C、坡度 ±2%、LDA 300–6000 m，纵向风分量为迎风至 30 kt、顺风至 10 kt、侧风至 25 kt；稳定风和阵风都检查范围。它支持干 / 湿跑道、FULL / CONF3、三档工程制动和 0–2 台反推。

积水、雪、冰、非均匀附着及 RCAM 等级没有被简化成“湿”而强行计算。FAA TALPA 的跑道状态方法用于说明这些状态需要独立建模。[FAA TALPA](https://www.faa.gov/about/initiatives/talpa)

本模块没有建模刹车能量、轮胎限制、爬升和障碍物、真实结构限值、故障着陆、自动着陆、发动机动态、侧向操纵及落地后油耗。后续若取得合法且适用的机型性能数据，应更换独立的参数与求解版本，并重新建立性能验证基线。

`tests/landing-engine-tests.cjs` 通过公共接口验证输入门控、独立机场、解析升力及恒减速度关系、干湿 / 风 / 温度 / 高度 / 坡度 / 构型 / 反推趋势、质量搜索边界、轨迹、快照与导出。初版共 24 项测试。纯模型与页面通过严格 TypeScript 检查；页面工作流验收由项目级浏览器测试覆盖。
