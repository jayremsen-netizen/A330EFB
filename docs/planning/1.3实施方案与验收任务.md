# A330EFB 1.3 实施方案与验收任务

实施基线为 1.2.1。目标是在本地浏览器中完成“航路燃油—配载重心—工程着陆—综合报告”的连续操作，保留旧起飞工程模型和已有演示。验收以实际计算、输入变更和文件往返为依据。

## 燃油规划

航路和备降分别由阶段及巡航航段组成。阶段输入时间与流量，巡航输入距离、TAS、迎风与流量。滑行、航路、应急、备降、最终储备及额外燃油分列，避免同一航段或滑行耗油重复计入。建议燃油只经明确操作写入计划；保存确认也不直接完成实际加油或装载。

完成条件：分项总和与建议停机坪燃油一致；不可实现的地速、燃油不足、容量和质量超限有明确结果；更改机场或航路文字后，旧航段必须复核关联；目的地和备降预计质量可供后续模块采用。

## 配载重心

四个客舱和三个货舱记录实际分配输入。总人数、行李与货物必须与航班合计一致，各阶段以质量和力矩计算重心，并绘制质量—重心包线。原生载荷页改用工程重心摘要；没有有效配载时显示空缺，不继续显示固定百分比。

完成条件：分区总量、质量和力矩可复算；前后移动载荷产生方向正确的重心变化；超出站位容量或包线不能确认；目的地与备降均经过校核；地面装卸按分区比例推进时守恒，满载和空载端点可验证。

## 工程着陆

目的地或备降场使用独立机场、跑道和气象对象。预计着陆重量取当前计划燃油账。模型以升力平衡、空中段假设、接地延迟和制动力积分形成速度及距离，比较 LDA，并在声明质量网格上搜索工程场长限重。

完成条件：解析公式和独立算例吻合；质量、风、湿道面、坡度等趋势正确；声明边界可算，包线外明确拒绝；输入变化立即撤下旧结果；短跑道保留可识别的诊断，导出报告不省略不可行状态。

## 集成与交付

航班文件保留三个输入及当前配载确认。长航段计划、空字段草稿、刷新和旧文件兼容均纳入测试。综合报告核对各模块之间的质量关系，生成 SVG 与 JSON 快照；自动演示通过实际控件完成七节流程。

交付检查执行严格领域类型检查、单元与启动验证、浏览器回归及仓库审查。GitHub 的 Windows、Ubuntu 从固定上游引用重新构建和验收，源代码、操作说明、截图及测试记录进入本仓库。最终结果见[验收记录](../verification/1.3验收记录.md)。
