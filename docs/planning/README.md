# A330EFB 1.3 工程计划

本版把航路及备降燃油、配载重心、工程着陆接入同一份航班。用途仍为投标演示：公式、输入、数值过程、图形和报告可以复核；飞机专用常数未经航空性能校准。

从“签派 → 综合工程计划”开始，或运行 `Start-EFB-Demo.ps1 -Scenario planning`。自动场景共七节，覆盖正常计算、采用燃油、确认配载、着陆距离不足、重新计算和综合报告。

## 数据与模块

`flight.ts` 保持原有航班模式，新增可选 `planning` 对象。三个输入分别保存，不共享出发与着陆气象。没有该对象的旧航班文件仍可导入；已编辑的工程输入随航班 JSON 和本机草稿保存。文件大小上限为 512 KiB，每组航路最多五十段。

`fuel-planning`、`loading`、`landing` 是无存储副作用的计算模块。`planning-context.ts` 负责采用关系：着陆重量取当前计划燃油账，配载确认同时校核目的地和备降条件，未采用的建议燃油不能直接成为着陆输入。`PlanningPages.tsx` 负责操作；`state.ts` 在航班确认后向签派页面同步时间、距离、油量和预计着陆重量。生成目录中的上游页面只由构建脚本叠加入口，Git 引用提交不变。

配载确认记录为本地内容指纹，用于检测输入变化，不是用户身份签名。燃油、载荷、模型参数等变化会撤销其有效性。着陆条件修改会撤下着陆结果；切换备降目标不会暗中沿用目的地跑道和天气。

综合报告在导出时按当前已确认输入重新计算，包含三个模块的输入快照和模型版本。正常结果、工程约束不满足、超出范围及输入无效分别呈现。短跑道结果标为诊断，不作为可采用速度。

## 支持边界

着陆模型覆盖声明质量和气象包线内的干、湿跑道，未覆盖污染跑道、障碍物、认证爬升、刹车能量、轮胎和故障性能。燃油按显式航段时间与流量计算，不解析 AIRAC 航路，未实现 ETOPS 或运行人批准的燃油政策。配载计算纵向静态力矩，站位、几何与包线为工程假设，未提供实际飞机配平设置或侧向重心。

这三项已经实现为可交互的工程演示功能；替换为航空运行产品仍需受控、适用的飞机数据和独立验证，不能仅改变界面标识。
