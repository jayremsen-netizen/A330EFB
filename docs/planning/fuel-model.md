# 航路与备降燃油工程模型

本模块为 A330EFB 投标演示提供可追溯的燃油预算。它把手工录入的航段、阶段油耗和储备策略换算为停机坪燃油建议，并检查当前计划和建议计划的质量约束。模型编号为 `A339-ROUTE-FUEL-ENGINEERING`，版本为 `0.1.0`。默认油耗率、时间与距离是工程样例，未经 A330 飞行试验或制造商性能表校准。

## 计算边界与资料依据

燃油分类参考 [EASA Air Operations 的 CAT.OP.MPA.181 及相关 AMC](https://www.easa.europa.eu/en/document-library/easy-access-rules/online-publications/easy-access-rules-air-operations?erules-id=ERULES-1963177438-12803)：滑行、航程、应急、备降、最终储备与额外燃油分别记录。EASA 对具体运行方案、假设条件及批准程序还有要求，本模块没有实现这些合规判定。默认的 5% 应急比例和 30 分钟等待参数只是可修改的演示策略。

[FAA Fuel Requirements Working Group 历史报告](https://www.faa.gov/media/32056)用于交叉核对燃油分类及备降阶段的术语，不作为当前法规适用性的依据。[Airbus Safety First 的燃油监控说明](https://safetyfirst.airbus.com/fuel-monitoring-on-a320-family-aircraft/)用于说明计划燃油与实际燃油需要分别监控；该资料面向 A320 系列，不提供本模型的 A330 油耗率。

模型不包含 AIRAC 航路解析、实时风场插值、飞机性能数据库、爬升能力、质量与温度对油耗的反馈、单发或减压关键燃油、ETOPS、再签派、无备降放行及多备降场方案。航路文字只用于关联与追溯，不参与距离计算。剖面的高度是可编辑示意高度，改变高度本身不会自动修正油耗。

## 输入与阶段划分

`FuelPlanInput` 保存当前出发、目的和一个备降机场的 ICAO、航路文字、总体来源、阶段来源及储备策略来源。每个巡航航段显式输入距离 NM、真空速 kt、迎风 kt 和油耗率 kg/h。迎风为正，顺风为负。

主航程依次为起飞及爬升、一个或多个主航路巡航段、目的地下降进近着陆。备降预算从目的地复飞开始，包括复飞及爬升、一个或多个备降巡航段、备降下降进近着陆。阶段表单的距离与巡航段距离分别累计，录入时不得把同一段距离重复分配给两者。

爬升、下降及复飞阶段使用手工时间、距离和固定油耗率。距离用于累计里程与剖面，时间直接决定燃油。允许零时长且零距离的阶段，以便把完整航程集中到显式航段中；零时长跨越正距离会被拒绝。每组巡航段须有 1–50 个条目，不能使用零或负地速。

滑行燃油统一取当前航班的 `taxiKg`，页面不维护第二份滑行输入。旅客、行李、货物和运营空重取当前航班，用于计算零燃油质量。机型固定为本项目 A330-941 配置。

## 燃油账与建议值

对第 i 个巡航航段：

```text
地速 GS_i = TAS_i − 迎风_i
时间 t_i（小时）= 距离_i / GS_i
航段燃油 F_i = t_i × 油耗率_i
阶段燃油 F_phase = 时间（分钟）/ 60 × 阶段油耗率
```

航程燃油等于主航程三个部分的燃油之和，备降燃油等于备降三个部分之和。储备按以下工程规则计算：

```text
应急燃油 = max(航程燃油 × 应急比例 / 100, 手工最低量)
最终储备 = 等待分钟 / 60 × 等待油耗率
建议停机坪燃油 = ceil(滑行 + 航程 + 应急 + 备降 + 最终储备 + 额外)
```

建议值向上取整至 1 kg，舍入增量单独保存为 `totals.roundingKg`。中间航段计算保留浮点精度，显示值的格式化不参与计算。目的地储备检查要求至少保有备降燃油与最终储备，备降着陆检查要求至少保有最终储备。当前停机坪燃油还必须达到整个建议预算，因此应急与额外燃油也计入计划是否满足的判断。

默认样例以 ZUTF—ZSPD、ZSSS 备降的演示航班为背景，主巡航输入 900 NM、450 kt、5,400 kg/h，备降巡航输入 25 NM、250 kt、5,000 kg/h。阶段另计。样例不声称这些距离对应实际航路；载入样例不会查询机场、航图或航路数据库。更换机场后必须人工核对。

## 名义着陆状态与约束

引擎同时计算 `planned`（当前计划燃油）与 `required`（建议燃油采用后）两套状态：

```text
起飞燃油 = 停机坪燃油 − 滑行燃油
目的地着陆燃油 = 起飞燃油 − 航程燃油
备降着陆燃油 = 目的地着陆燃油 − 备降燃油
各阶段飞机质量 = 零燃油质量 + 对应燃油
```

这些是未消耗应急、额外和最终储备的名义状态。实际等待、复飞及异常耗油会改变着陆质量。若当前计划很少甚至为零，允许计算燃油缺口；派生燃油账的负值表示航程不可达。页面不把对应质量显示为可用着陆质量，下游性能模块也不能采用该状态。负的录入燃油值则直接判为无效输入。

油箱容量沿用本项目的 36,743 美制加仑与固定 3.039 kg/加仑换算；MTOW 为 251,000 kg，MZFW 为 181,000 kg。目的地与备降 MLW 均使用 191,000 kg，作为项目各工程模块一致的演示约束。这些检查不能替代适用机号的 AFM、燃油密度、实际机型重量限制及运行批准。

`status` 有四种结果：输入或关联错误为 `invalid`；当前与建议计划均通过为 `engineering-feasible`；当前燃油不足但建议可行为 `engineering-shortfall`；任一质量或容量检查超限为 `engineering-limit-exceeded`。`canApply` 专门表示建议计划的质量与容量可行性，因此当前计划过少或过多时，仍可采用一份可行建议。建议本身超限时，采用按钮禁用。

## 关联、失效与采用

`fuelPlanSignature` 只选择航班身份、机场、航路、机型、载荷、运营空重、停机坪燃油和滑行燃油，加上本模块输入与模型定义生成签名。它不序列化整个 `Flight`，避免 `Flight.planning.fuel` 自引用，也避免无关的着陆页面设置改变燃油数值。

任何有关输入变化都会使页面已显示的计算结果失效，旧数字、SVG 与采用入口当即撤下。出发、目的、备降或航路文字变化时，保存的航段输入继续保留，但计算返回关联错误。用户核对手工航段后，必须点击“已复核手工航段，关联当前机场与航路”才能重新计算。

“采用建议停机坪燃油”仅调用父页面的 `onApplyFuel(requiredRampKg)`。父页面重新计算并核对建议，之后只修改航班计划的 `rampKg`。实际油箱加油、地面作业状态、载荷与滑行耗油均由各自模块管理。采用后必须重新确认航班重量和受影响的性能结果。

## 接口与可追溯输出

```ts
defaultFuelPlan(flight: Flight): FuelPlanInput
validateFuelPlan(flight: Flight, value: unknown): string[]
calculateFuelPlan(flight: Flight, input: FuelPlanInput): FuelPlanResult
fuelPlanSignature(flight: Flight, input: FuelPlanInput): string

interface FuelPlanningProps {
  flight: Flight;
  input: FuelPlanInput;
  onChange: (input: FuelPlanInput) => void;
  onApplyFuel: (requiredRampKg: number) => void;
  disabled?: boolean;
}
```

结果保留输入快照、参与计算的航班字段、模型编号与版本、计算时刻、签名、各段时间和燃油、分类合计、两套质量状态以及每项约束。目的地与备降的核心字段分别为 `destinationLandingFuelKg`、`destinationLandingMassKg`、`alternateLandingFuelKg`、`alternateLandingMassKg`。

页面可导出完整 JSON 和独立 HTML 报告。报告内的剖面按实际录入距离绘制，目的地处分隔主航程与备降段；燃油比例条按本次六类计算值绘制。文字、航路、来源和 JSON 均经过 HTML 转义，报告无需外部图片或网络请求。

## 验证依据

执行 `node tests/fuel-planning-tests.cjs`。独立算例设置主巡航 600 NM、300 kt、6,000 kg/h，爬升 10 分钟、下降 5 分钟；备降巡航 120 NM、240 kt、6,000 kg/h，复飞 2 分钟、备降下降 3 分钟。所有阶段油耗率为 6,000 kg/h。

算例得到航程 13,500 kg、备降 3,500 kg、5% 应急 675 kg、30 分钟等待最终储备 2,000 kg、额外 500 kg、滑行 500 kg，建议停机坪燃油为 20,675 kg。计划 30,000 kg 时，目的地燃油为 16,000 kg，备降燃油为 12,500 kg；采用建议后分别为 6,675 kg 和 3,175 kg。

回归覆盖完整燃油账、输入非法值、不可前进地速、机场与航路失效、容量及各项质量限制、低燃油可计算建议、迎顺风方向性、额外备降航段、最低应急量、舍入、滑行单计、输入快照隔离、签名边界与导出转义。测试生成 `.artifacts/fuel-planning/tests.json`，综合页面的交互与跨模块联动由项目 UI 验收执行。
