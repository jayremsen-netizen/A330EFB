# A330EFB 投标演示版完善方案

版本 1.1　2026年10月4日

本方案将 A330EFB 完善为可以离线运行、接受现场自由操作、完整演示主要业务流程的投标软件。实施从提交 5df1664 开始，首先解决复盘发现的数据与计算缺陷，再补充离线资料和本地运行状态演示，最终以实际程序、自动测试和独立构建记录作为交付依据。

## 一 建设目标与完成条件

目标版本为 A330EFB 1.1。用户能够从本地航班建档进入载荷燃油核对、天气选择、参考计算、航图阅读、地面准备、检查单及报告归档，也能够暂停自动演示后直接修改输入。软件应清楚表达输入错误、资料不支持、地面操作未完成和结果已过期，保持页面数据可以相互解释。

完成条件包括九类复盘问题均有处置和回归证据、离线资料与地服故障演练可以操作、四套工作流通过外网阻断测试、异常存储不再造成整页退出，以及 Windows 和 Ubuntu 从固定上游引用构建成功。两个 Word 文件、任务清单、验收记录和源码一起保存到 GitHub。当前无法取得可靠依据的性能范围必须明确拒绝输出，不用猜测系数填补结果。

机型范围保持 A330-941 与 Trent 7000。真实飞机或模拟器接入、商业航图订阅、组织权限、跨设备协同数据库和完整起飞放行性能列入后续工程。本版的地服与故障状态由本地模型演示，界面持续标明来源。

## 二 现状与改造依据

既有工程已经具备固定版本构建、航班工作台、重量计算、参考 V2、报告和三套自动演示。复盘重新运行的 25 项单元检查及 25 项浏览器检查均通过，但新增边界探针复现了负着陆距离、货舱容量截断、单位语义错误、草稿恢复失败、异常历史崩溃、多窗口覆盖、低油量分配不一致、语义校验遗漏及旧手册页码引用。

上述问题分别涉及领域规则、宿主适配、持久化及演示资料，不宜通过调整默认演示输入绕开。改造保留现有主要页面与有效流程，在本项目源码中增加规则和适配；上游继续采用固定 Git 引用，构建脚本完成可核对的局部集成。

## 三 系统结构与数据职责

浏览器继续承载界面和本地领域服务，Node 服务分发静态资源。新增加的单位与油箱分配模块供宿主和计划同步共同调用；持久化模块负责草稿格式、结果校验、异常隔离和保存冲突；离线资料模块提供航图索引与天气样例；本地运行模型处理地服、故障和预设的命令及状态变化。

Flight 表示准备采用的业务计划，运行目标表示希望达到的状态，运行快照表示本地仿真当前状态。点击操作后先显示执行状态，完成后才更新相应当前值。计划修改使已有结果失效，运行目标变化需要明确带回计划确认，不能从页面之间静默传播为已批准输入。

对外部服务保留扩展位置，但演示的关键路径全部在本机执行。离线航图及天气携带资料标识、来源、时间和适用范围；用户导入文件与程序自带样例区别显示。用于说明的机场示意图不得采用真实航图外观而省去演示标记。

## 四 计算与质量一致性改造

着陆工具增加输入与结果守卫。现有重量修正的注释和实现有十倍量纲疑点，当前依据不足以选择其中一个作为真实算法。本版将着陆输出限定在已经建立软件算例的 190000 kg 基准重量，其余重量显示不支持并清空旧结果。所有输出必须为有限正数；这项防护不等于完成机型性能校准。取得可靠资料后再按独立版本扩大模型范围。

起飞计算继续提供源码 V2 参考，增加 CONF 3 的 220 至 230 吨疑点区间拦截。确认前检查旅客人数、旅客与行李单重、货物及行李合计、油量、结构质量和跑道声明距离。货舱合计不得超过机型配置的 44836 kg；任何超限均在计划层拒绝，不允许原生页面悄悄截断后继续保留旧质量。

宿主变量采用明确的规范单位。质量内部使用 kg，油箱量使用 US gal，高度使用 ft，角度使用 degree。读取和写入均经过转换，注册变量保留请求单位。油箱分配采用内侧首段、外侧、内侧剩余容量、中央油箱的相同规则，计划初始化与目标写入共用一份函数，保证总量守恒和两侧对称。

## 五 草稿保存与异常恢复

草稿和可计算输入采用不同校验层。清空的数值字段以可序列化的空值保存，恢复后仍保持空白，航班号等其他输入保持原样；只有保存确认或计算时才要求完整合法数据。日期按实际年月日核对，必填航班身份不能留空，跑道编号限定为 01 至 36 及合法后缀。

恢复时分别检查航班、确认身份、结果和历史记录。坏记录进入恢复备份，并向用户说明被隔离的数量；有效记录继续使用。当前结果需要核对输入身份、资料版本和数值结构，不能因为存储中标有有效就直接采用。用户能够导出恢复备份，后续编辑不得覆盖唯一原文。

同源多窗口通过保存前版本比较和存储事件发现冲突。检测到其他窗口保存时，当前窗口保留可导出的输入并停止写入，用户选择读取最新版本后继续。此方案用于单机窗口协调，不扩展为多人协同或服务端事务。

## 六 离线资料与天气

新增离线资料入口，提供程序自带机场示意图、资料索引、缩放、旋转、收藏及恢复浏览。支持用户选择 PDF、PNG 或 JPEG，按大小和文件特征检查，使用浏览器本地对象地址阅读；文件离开会话后的保存边界在页面上说明。导入失败保持原有图件，旧对象地址在替换时释放。

天气页提供有明确样例标记的机场天气和来源时间。选择天气后，只有用户点击采用才把风、气温和气压写入当前计划，并撤销旧确认和计算结果。仪表盘和签派兼容字段使用同一组样例资料，避免工作台已变而原生页面仍显示另一份天气。

## 七 地服故障与预设演练

本地运行模型实现外接电源连接、按计划加油、登机和简化推出的状态演示。命令保存唯一标识、类型、参数、开始时间、状态和进度，能够区分已接受、执行中、完成、拒绝和失败。同一命令标识重试不会重复执行；重置会话取消旧动作，旧计时回调不能污染新会话。

故障演练至少覆盖外接电源故障和加油故障。故障需要改变对应服务的可用性或执行结果，解除后允许重新操作。推出前检查外接设备、登机和加油是否仍在执行，条件不满足时给出原因。预设只改变本地演练模型中明确列出的状态，并显示实际完成情况。

这些行为用于展示状态协议和操作工作流，不推断真实飞机系统效应。浏览器中依赖尚未接通宿主的入口应转入可用的本地演练，或清楚表达不可用原因，防止评委点击后停留在无反馈状态。

## 八 自动演示与文档对应

保留典型航班准备、地面变更重算和专业工具巡览三个场景，新增资料与地面协同场景。新场景展示天气采用导致结果失效、离线图件阅读、地服请求完成、故障导致拒绝及解除后恢复。所有步骤操作实际页面并核对业务状态，不能用替换截图作为功能执行。

暂停、重播、定位、场景切换和资料导出继续使用独立演示存储。讲解引用改为明确的文档版本与稳定章节号，不再固化旧 PDF 页码。新版功能以 1.1 操作补充说明配套交付，并在主 README 中明确现行文档入口。

## 九 实施顺序与验收组织

实施分为四个里程碑。M1 固化方案与复盘基线；M2 关闭计算、单位、质量及存储问题；M3 完成离线资料和运行演练；M4 完成回归、文档、独立构建和 GitHub 交付。任务有代码和证据才标为完成，未解决问题不得以调整说明文字替代。

验收由自动检查与人工观察共同构成。自动检查验证输入约束、恢复、冲突、命令状态和业务结果；人工检查验证提示能否理解、页面是否可阅读以及自由操作是否有明确反馈。目标分辨率为 1920×1080 和 1280×720；窄屏检查验证页面可访问与滚动，不把缩小后的桌面仪表认定为完整移动端产品。

## 十 交付与版本控制

交付包括完善方案、实施任务书、可追踪任务清单、软件源码、原始自制资料、测试与运行脚本、操作补充说明及验收记录。既有两个上游提交保持锁定；第三方源码由构建获取，不提交复制品或 node_modules。新增文件不包含账号令牌或用户浏览器数据。

发布前执行构建、单元检查、离线浏览器回归和仓库审查。通过后提交 GitHub，并检查远端 Windows 与 Ubuntu 作业。交付记录注明最终提交、命令、结果和限制；Word 中的完成状态只在对应证据形成后更新。
